SchoolRun
A PWA school bus management platform for Nigerian private schools — giving schools real-time fleet visibility and parents real-time tracking of their children.

1. Project Overview
SchoolRun is a school bus management system built on a Django backend and a Progressive Web App (PWA) frontend. It connects four roles — school administrators, parents, drivers, and marshals — and provides real-time bus tracking, student check-in/check-out, route management, and parent notifications.

Core target user: The 9-to-5 commuting parent at Nigerian private schools.

Core value proposition: Solve the safety visibility and route efficiency problems in school bus operations through a software layer — giving schools auditable transport management at minimal cost, and giving parents real-time information about their child's location and status.

MVP scope: Real-time bus tracking, student QR code check-in, parent Web Push notifications, school admin dashboard. Camera streaming and AI route optimization are deferred to later versions.

Why Not React/Vue for the MVP?
Django templates + vanilla JavaScript is sufficient for the MVP. Avoid introducing a frontend build toolchain to shorten development time. Migrate to React later if more complex state management is needed.

Why Not PyZbar?
QR scanning happens entirely in the browser using jsQR. PyZbar would require an extra system library (libzbar) and server-side image upload, which is unnecessary. The server only needs to generate QR codes (via the qrcode library), not decode them.

6. Core Feature Implementation
6.1 Real-Time Location Tracking (WebSocket)
Driver PWA logic:

text
Driver taps "Start Trip" → requests Geolocation permission →
sends {lat, lng, trip_id} via WebSocket every 10 seconds →
Django Channels consumer receives, writes to LocationLog, and broadcasts to parents subscribed to that route →
Parent-side map Marker updates
Key limitation: PWA cannot access GPS in the background on iOS Safari. The driver must keep the page in the foreground. During the MVP, display a clear prompt in the UI: "Please keep this page open to continue tracking."

Technical implementation: Django Channels + Redis as the layer. Consumer uses AsyncJsonWebsocketConsumer, routed at /ws/tracking/<trip_id>/.

ASGI server: Channels requires an ASGI server to run. Daphne is included in requirements.txt and is used to run the app in both development and production (daphne schoolrun.asgi:application). Django's runserver command will also serve ASGI when daphne is in INSTALLED_APPS, but production uses Daphne directly.

6.2 Off-Route Detection (PostGIS)
When a location update arrives, the backend checks the distance between the current position and the route's path LineString:

python
# tracking/services.py
from django.contrib.gis.db.models.functions import Distance
from django.contrib.gis.geos import Point
from schools.models import Route

OFF_ROUTE_THRESHOLD_M = 500

def check_off_route(trip, lat, lng):
    point = Point(lng, lat, srid=4326)
    route = trip.route
    distance = route.path.distance(point) * 111_320  # degrees to meters (approx)
    if distance > OFF_ROUTE_THRESHOLD_M:
        return True, distance
    return False, distance
Note: For accuracy, use PostGIS ST_Distance with a projected coordinate system rather than the degree-to-meter approximation. The approximation is acceptable for the MVP.

6.3 Student QR Code Check-In
QR code generation (at student registration):

python
# students/services.py
import qrcode
from io import BytesIO
from django.core.files import File

def generate_student_qr(student):
    qr = qrcode.QRCode(box_size=10, border=2)
    qr.add_data(str(student.id))
    qr.make(fit=True)
    img = qr.make_image(fill_color="black", back_color="white")
    buffer = BytesIO()
    img.save(buffer, format='PNG')
    filename = f"qr_{student.id}.png"
    student.qr_code.save(filename, File(buffer), save=True)
Check-in flow:

text
Marshal opens PWA → taps "Scan Student" → opens camera →
jsQR decodes the QR in the browser → frontend gets student_id →
POST /api/checkin/ {student_id, trip_id, type} →
Django records CheckIn → triggers Celery task to send Web Push →
Parent receives notification: "[Student name] boarded at 07:42"
Why QR codes instead of NFC: iOS Safari does not support Web NFC. NFC is essentially unusable in a PWA. QR codes only need camera permission, which PWAs support, and printing costs are minimal.

6.4 Parent Web Push Notifications
Notification triggers:

Bus is < 5 minutes from the student's stop (calculated from live location and stop coordinates)

Student boards successfully (check-in)

Student alights successfully (check-out)

Bus deviates > 500m from route (PostGIS geofence)

Technical implementation: Service Worker registration + Push API. Subscription data is stored in the PushSubscription table. Celery tasks send notifications via pywebpush. After the parent grants notification permission in the PWA, they receive notifications even when the app is closed.

6.7 Scheduled Cleanup (Celery Beat)
The 30-day location retention policy is enforced by a Celery Beat scheduled task:

python
# tracking/tasks.py
from celery import shared_task
from django.utils import timezone
from datetime import timedelta
from tracking.models import LocationLog

@shared_task
def purge_old_location_logs():
    cutoff = timezone.now() - timedelta(days=30)
    deleted, _ = LocationLog.objects.filter(timestamp__lt=cutoff).delete()
    return f"Deleted {deleted} location logs"
Celery Beat schedule (in settings.py):

python
CELERY_BEAT_SCHEDULE = {
    'purge-old-location-logs': {
        'task': 'tracking.tasks.purge_old_location_logs',
        'schedule': crontab(hour=2, minute=0),  # daily at 2am
    },
    'check-credential-expiry': {
        'task': 'compliance.tasks.check_credential_expiry',
        'schedule': crontab(hour=6, minute=0),  # daily at 6am
    },
}
Important: Celery Beat is a separate process from the Celery worker and must be started independently. See the startup section below.

7. Compliance Requirements
7.1 Child Data Protection (NDPA 2023)
SchoolRun processes children's personal data and is strictly regulated by the Nigeria Data Protection Act 2023. The NDPC (Nigeria Data Protection Commission) explicitly emphasizes that platforms have a "Duty of Care" regarding children's data.

Mandatory actions:

Obtain explicit parental consent: At student registration, the parent must explicitly agree to data processing via a checked confirmation box. Silence does not constitute consent. Consent is recorded in the ConsentRecord table.

Data minimization: Collect only necessary fields (name, class, stop, parent contact). Do not collect birthday, home address, or other non-essential data.

Data retention policy:

Location history (LocationLog): retained 30 days, auto-deleted by Celery Beat

Check-in records (CheckIn): retained for one academic year

QR codes: deleted after the student leaves the school

Consent records: retained for the duration of enrollment plus 7 years (legal requirement)

Privacy policy: Written in plain English explaining data use, retention period, and parent rights (access, deletion, withdrawal of consent).

7.2 Nigerian School Bus Operating Standards
According to NIS 716:2010 "School Bus Operating Guidelines":

School buses must have a yellow base color + two white stripes, labeled "SCHOOL BUS"

Drivers must have 5+ years of driving experience, no criminal record, and pass a medical exam

Every vehicle must have a marshal on board

Operators must hold a School Bus Operator's Permit (valid for 3 years)

SchoolRun's software role: Sell as a compliance tool to schools — providing driver qualification expiry reminders (via the DriverCredential and VehiclePermit tables), trip log exports (for audits). The software itself does not replace legal compliance requirements; it helps schools meet them more easily.

11. First Step After the MVP
Find a pilot school. Do not wait for the product to be "perfect" before selling. An MVP that can demo real-time tracking + check-in notifications is enough to get a private school principal to agree to a one-term trial.

The core value of a pilot school is real data:

Actual route run times (input for the optimization algorithm)

Real parent usage behavior (which notifications get opened/ignored)

Real pain points from the school administrator

With pilot data in hand, you'll be qualified to apply for the CcHUB EdTech Fellowship (up to $100,000 in funding).
